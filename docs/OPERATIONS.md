# 运行、升级与恢复

## 运行方式

默认本机发行：DEBUG 关闭，可信 Host 为回环名称，Waitress 监听 127.0.0.1，独立 worker 执行持久化任务。`launch-platform.ps1` 先检查迁移、生成静态资源，再记录启动进程与创建时间；健康接口和监听 PID 同时匹配后才打开浏览器。停止仅针对仍匹配身份的进程。端口被其它程序占用时失败，使用 `-Port` 指定其它端口。

手工运行可分别执行 `python -X utf8 manage.py serve --port 8000` 与 `python -X utf8 manage.py worker`。仅个人版单 worker；任务租约过期标记失败并解除阻塞，不会假称自动续跑。视频、备份已异步；网页抓取、部分 AI/OCR 仍同步。没有完整用户取消、所有阶段重试、临时文件到期清理或操作系统 CPU/内存沙箱。

## 环境变量

| 名称 | 默认/用途 |
|---|---|
| ZHISHIKU_DEBUG | 0；本机开发可设 1，发行不要开启 |
| ZHISHIKU_SECRET_KEY | 未设置时在源码目录独占创建 .instance-secret；每实例独立 |
| ZHISHIKU_ALLOWED_HOSTS | 127.0.0.1,localhost,[::1] |
| ZHISHIKU_DB_PATH | 源码目录/db.sqlite3 |
| ZHISHIKU_MEDIA_ROOT | 源码目录/media |
| ZHISHIKU_DATA_ROOT | 源码同级/ZhiShi |
| ZHISHIKU_BACKUP_ROOT | 源码同级/备份输出 |
| ZHISHIKU_LOG_DIR | 源码目录/logs，轮转单文件 5MB，最多保留 5 个旧文件 |
| ZHISHIKU_UPLOAD_MAX_BYTES | 64MiB；并限制格式/真实类型/解压量与解析页数 |
| ZHISHIKU_BACKUP_MAX_BYTES | 8GiB；写入和恢复同时限制 |
| ZHISHIKU_ALLOW_PRIVATE_FETCH | 0；明确授权内网网页时才能设 1 |
| ZHISHIKU_ALLOW_AI_OUTBOUND | 未设置时读取管理员页面 allow_ai_outbound，默认 0；设 1 允许云端外发 |
| ZHISHIKU_AI_ALLOW_FALLBACK | 0；设 1 才允许请求失败后改用其它启用服务 |
| ZHISHIKU_NETWORK_MODE | 0；设 1 必须独立环境密钥、明确 Host 并启用 HTTPS Cookie/HSTS |

例子文件不会自动加载，变量需要放在启动环境。新文件路径以存储根+相对路径解析，旧绝对路径仅在允许根内兼容；外部工作目录独立核对。

## 权限、秘密与 AI

业务页面需要登录；设置、备份、诊断需要管理员。账号共享同一份个人知识，不提供每用户/每库所有权隔离。写操作要求 CSRF，原件经登录保护；HTML/文档下载作为附件并隔离主动内容。

新 AI/Gitee 凭据保存到操作系统凭据存储，数据库仅存引用。支持 `env:VARIABLE_NAME` 引用环境秘密。凭据存储不可用时明确报错，不回退到明文数据库。服务配置页仅显示已配置/掩码。旧明文配置为兼容读暂保留，管理员可在旧实例执行 `python -X utf8 manage.py migrate_secrets`；先确认本机凭据存储可用。该操作是显式命令，读取设置页不会偷偷迁移。

系统凭据命名空间与实例密钥绑定；换机或修改密钥后应重新配置 API 凭据。备份副本移除 AI Key 与 Gitee Token，不修改源数据库秘密。正文、账号哈希等仍可能敏感，包没有加密/数字签名。

云端资料外发默认关闭；开启后所选服务会收到提交的资料。失败跨服务转发仍单独默认关闭。本机服务需勾选“本机服务”，地址限制回环，可取消鉴权要求。字符预算不等于精确 Token 预算；API 错误不会作为模型回答入正文，现有正文的 AI 改稿需要审核。

## 升级已有实例

1. 保留原实例代码、完整数据库、知识目录、媒体原件、配置和本机凭据的恢复方式。旧版运行中直接复制 SQLite 不可靠；停服务后复制，或使用支持一致快照的新备份机制。
2. 在新目录复制实例并保留原目录。使用独立虚拟环境安装锁文件，执行迁移。不要用源码包覆盖解压生产目录，也不要让测试进程连接原用户数据库。
3. `init_config.py` 只补新默认项，保留已有配置。迁移为新节点加入版本/导出状态，为旧 archive 记录增加归档标记；原类别已经丢失的历史数据保持 archive，待人工核对。
4. 关系唯一约束迁移把全部旧重复记录保存到 DeletedNode 的迁移快照后再保留规范关系；不猜测同名目标或旧分类。旧标题导出文件保留，新保存使用节点 ID，不扫描旧文件自动重新入库。
5. 检查管理员登录、知识/书籍/办公原件、导出、上传、版本冲突和样例恢复。运行诊断可重试失败导出。确认完成后再切换启动入口。
6. 回滚使用整套旧实例/旧备份。不要只覆盖旧代码或任意倒退迁移来回滚包含新版本记录的数据。

本次优化仅在新克隆和隔离数据中验证，没有升级原用户实例。现有旧原件不会自动全部改写为 Asset；按需解析/后续迁移，保留原文和人工修改。删除知识节点走回收站；完整数据生命周期与所有其它对象的回收机制尚未完成。

## 备份与恢复验证

备份用 SQLite Online Backup API 建快照，经 integrity_check 校验；JSON 导出从同一快照读取。新不可变 Asset 依据快照校验原件哈希。包逐文件记录哈希与大小，临时写入、容量检查、整包验证后才原子发布。关键原件缺失/数据库导出失败会使任务失败。

数据库与新不可变原件有一致边界；仍可变的历史办公文件不具备文件系统级快照，备份期间应避免手工改动或删除。生成 ZIP 成功只是备份验证的一部分，需要定期隔离恢复。

```
python -X utf8 manage.py verify_backup "BACKUP.zip"
python -X utf8 manage.py restore_backup "BACKUP.zip" --destination "NEW_FOLDER"
```

仅支持本版本 format_version=2 的可信备份。恢复拒绝已有目标、重复/越界路径、资源超限、清单不符和哈希不符；在临时目录运行迁移与导入，检查完整性/外键，再发布到新目录。迁移包保留账号，知识/系统包需创建管理员，均需重配凭据。已知书籍/工作文件/报告路径按包的旧根映射新目录，外部目录保留旧值并写入「恢复验证.json」待核对。

恢复验证并非对每个历史文件格式的完整阅读验收。应抽样打开原件、书籍、知识、办公产物并处理验证报告，再切换。没有合并导入、覆盖已存在目标、旧包自动升级或包数字签名；不要恢复陌生代码包，哈希不是来源真实性保证。

## 网络部署边界与检查

目前推荐本机使用。网络部署的配置基线已加入，但仍需可信 HTTPS 反向代理、静态/媒体策略、明确出站允许清单、文档/对象权限、并发与恢复演练。程序不盲目信任代理转发头；HTTPS 代理集成要按实际拓扑单独配置，否则可能出现重定向循环。

本机 HTTP 执行 `check --deploy` 会给出 5 个提示：HSTS、SSL 重定向及两项 Secure Cookie 告警对应有意的本机 HTTP 配置；W019 对应 SAMEORIGIN，用来保留 SimpleUI 管理后台所需的同源嵌入，同时拒绝其它站点嵌入。网络模式保留 2 个提示：上述 SAMEORIGIN，以及 W021（未开启 HSTS preload），后者是避免未经域名运营确认提交预加载。不能以这些检查代替实际网络渗透/SSRF/多租户验证。

## 测试与依赖

回归测试包括认证、CSRF、注入、不可变原件、路径边界、冲突/回收站、SQL 查询增长、逐页 PDF、失败导出、任务中断、WAL 在线备份、篡改包、新目录恢复及浏览器流程。故障注入的 ERROR 日志是预期测试条件，最终以测试结果为准。

Windows 的 Python 3.11/3.12 已本机执行；Ubuntu/多版本仅配置 CI，尚未运行。可选视频/OCR/语音工具未安装实测；模拟超时与参数上限测试不等于整条工具链验收。程序与依赖版权状态见 DEPENDENCIES.json，需要另行核对原仓库许可与第三方分发条件。
